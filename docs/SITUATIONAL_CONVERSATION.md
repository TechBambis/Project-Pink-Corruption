# Situational conversation

Choose **Voice & AI → Conversation & memories → Conversation style → Situational**. This is the web app's default. **Classic** retains the existing authored prompt and continuous narration behavior. The style is saved with other preferences and included in AI preparation.

The model chooses its contribution from the conversation: answer a question or correction, ask one focused question whose answer matters now, develop a short guided passage, or close the session. There is no questionnaire, question quota or predetermined psychological goal. After an answer, the next contribution should use its actual content. Selected cue spellings, character style, current phase and the selected language intensity inform guidance. Intensity adjusts delivery and repetition, and does not establish a measured hypnotic effect.

A contribution marked `ask` stops at its first question mark. Automatic narration waits after the question has actually played or been displayed in text mode. A rhetorical invitation marked `guide` does not open a reply window. Pauses reach speech rendering while control markers stay out of chat. Interrupted and unplayed speech cannot establish an answered question or an experienced sensation. Engine continuation requests are not saved as listener statements. A new conversation clears the temporary question/input state while retaining the existing saved-memory behavior.

The model selects `respond`, `ask`, `guide` or `close` through a streaming `[turn:...]` header. The server accepts capitalization, whitespace and a trailing colon, and removes that metadata before display, speech and history. It reports `expectsReply` on playback completion. Without recognized metadata, a completely delivered contribution ending in a question mark is classified as `ask`; unfinished or unheard questions and closing contributions do not open a reply window. An explicit `guide`, `respond` or `close` remains authoritative, including rhetorical question endings. Punctuation fallback is a heuristic: it cannot reliably distinguish an unmarked rhetorical question from a real request for an answer. It does not truncate ordinary unmarked explanations at an internal question mark. Situational mode retains the complete selected authored prompt, including enabled collar content and strategy. Its conversation contract controls turn choice and gives current listener corrections and engine facts priority over conflicting character examples. The audiovisual envelope is reported separately from the selected language intensity. Runtime instructions favor accurate recall and immediate corrections, and treat silence as unknown. No second planning model or added inference call is required.

The mode applies to live conversation and automatic narration. Authored timed event programs and imported recordings retain their existing schedules. Old API clients default to `interaction: "reactive"`; clients can request `"situational"` and mark autonomous continuations with `source: "engine"`.

Character selection is shared by preparation, chat and generated event narration through `packages/ai/character.ts`. Classic and Gentle retain their complete authored documents, including enabled collar content and strategy; Custom uses the listener's personality text. Shared language and speech compatibility in `packages/content/voice.ts` do not impose an additional dominant personality, reward system or fixed reply length. Greeting instructions retain the selected character's own tone.

Every character receives `packages/content/interaction.ts` after its authored text. Fictional scene memories may be part of the chosen story, but they must not be presented as actual past listener statements, consent or confirmed preferences. Real factual recall uses conversation evidence; current corrections and limits take precedence over conflicting character examples. This is model guidance, not a guarantee of compliance by any particular model.

Stable header semantics and intensity/output rules live in the reusable fixed prefix. Per-turn guidance keeps the action reminder, the distinction between real listener input and engine continuation, the current phase for guided passages, and the word budget. Conversation receives only phase/scene/intensity facts; narration additionally receives progress, remaining time (or unlimited status), the audiovisual envelope and relevant cues. Trigger timing is compact and included only when enabled. The same short guidance is used across backends, without guessing a model's parameter count from its name. Actual inference quality and tokenizer cost need measurement with the chosen model.

Verification covers fragmented headers, question cutoff, answer windows, interrupted/unheard questions, pause handling, conversation reset and the production server path with deterministic LLM/TTS fixtures. Run `npm test` and `node scripts/dialogue-server-check.mjs`. These checks establish playback and state behavior; they do not establish that a particular local model asks well-timed questions or produces more immersive audio. That requires listening trials with the chosen model and voice.
