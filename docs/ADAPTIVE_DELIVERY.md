# Adaptive narration delivery

**Voice & AI → Adaptive narration: pace, pauses & mix** enables engine-selected delivery for continuous narration, including Situational and Classic sessions. Conversation replies retain the selected voice speed. Finished files retain their original audio.

The engine chooses a delivery mode once per passage inside the existing five parent phases: induction 24%, deepening 16%, conditioning 40%, anchor 10%, awakening 10%. These modes are not additional phases.

| Mode | Speed relative to your setting | Phrase gap | Maximum passage words | Pause relative to phase setting |
|---|---:|---:|---:|---:|
| Settle | 0.90× | 650 ms | 50 | 1.50× |
| Guide | 1.00× | 350 ms | 75 | 1.00× |
| Drive | 1.35× | 140 ms | 85 | 0.55× |
| Hold | 0.86× | 900 ms | 35 | 1.80× |
| Return | 0.96× | 500 ms | 150 | 1.20× |

The speed remains within 0.5–1.5. Closing budgets shrink with the remaining session time. The engine reserves the last eight seconds from new autonomous requests. A sentence finishes before the generation word limit is enforced; spoken audio remains subject to the configured session end. Existing question/answer waiting behavior remains active in Situational mode.

Generated background and supporting voices become quieter in sparse passages and return smoothly in denser ones. Multipliers sit after user faders; they do not enable disabled backgrounds, raise a zero fader, change your master level, or process the original file bus. The main voice stays in the foreground. Transitions use approximately 450 ms to approach their new gain. Existing speech ducking and limiting still apply.

With **automatic phase visuals + visual journey** enabled, the matching orb/spiral presentation changes when the passage starts reaching the output device. It stays stable while that passage is generated and spoken. Manual visuals and imported scene timelines remain authoritative. Reduced motion and the final audio-only fade remain effective. Narration receives screen facts only when those visuals will actually be available.

The LLM receives a bounded original text task and a syntax direction. It does not select timing, repetition or effects. Engine-controlled phrase timing replaces model-written pause annotations for adaptive narration. Word captions and the inline reply continue to use measured TTS timestamps, not token arrival.

Authored native events have a separate optional `speech.delivery` field. Their fixed speech windows, cached mantra payloads, cue alignment and engine-only blanks remain authoritative. Isolated event TTS does not add renderer phrase gaps; the event owns the remaining interval. Measured pace correction is stored separately by speech mode, delivery mode, selected speed, voice and preset.

Generated event narration now resolves the same complete selected Classic, Gentle or Custom character as chat and preparation, including selected cues and enabled collar text. The guided narration style is a separate delivery preference within that character. The event output contract overrides character examples that conflict with plain text, reserved cues, word budgets or presentation facts. Full character instructions are checked against the model's context capacity and are not silently shortened. Older event clients that send only persona text retain a Custom character default. Fixed authored audio/text cues such as Blink remain engine-owned and do not invoke character generation.

Native 9B event requests use the existing checkpoint mechanism with a stable complete-character/event prefix. Changing optional clock/place context is moved into the application-context message, rather than changing that reusable prefix. This preserves the existing caching architecture; actual latency still depends on the model and hardware.

Validation includes the complete unit suite, real local Kokoro renders at multiple speeds, browser checks of output-timed visual changes and Pause/Stop, and real offline audio rendering of gain transitions, zero faders and original-file passthrough. A headless browser with mock narration does not establish subjective listening quality or a complete physical-device session.

## Adaptive session direction (development)

Choose **Guided session** to enable the director and spoken narration. Advanced options remain under **Session → Advanced session controls → Adaptive session direction**. Leave the authored-program input empty, or choose **Use adaptive direction** after loading a program. This is a separate path from the continuous-narration delivery switch above. Imported authored programs still execute their supplied timeline; finished library tracks retain their original audio and timed-cue path.

**Session → Session direction** offers Balanced, Reference contrast (Tom Tame-inspired audiovisual structure), Slow immersion and Rhythmic immersion. Expand **Fine-tune this style** to adjust contrast, recurrence, voice rhythm, visual motifs, narrative focus and seven optional mechanisms. Edits become Custom and persist across reloads. Settings influence future uncommitted episodes; they do not change current prepared audio, voice identity, user faders or fixed parent proportions. The style panel is contextual to adaptive Guided sessions, and disabled for imported authored programs. See [Session direction](SESSION_DIRECTION.md) for the component contract, extension path and test scope.

### Unlimited duration

**Unlimited** is the default session duration for Chat and generated Guided sessions. There is no automatic transport end. The engine uses recurring 20-minute journeys with the existing 24/16/40/10/10 parent proportions to keep phase-dependent voice, visuals and optional device automation coherent. The elapsed counter, adaptive history, motif identities and cue cooldowns persist across journeys. New episodes are planned; this is not a replay of a fixed 20-minute script.

The final tenth of each journey offers a quieter return and reorientation, without announcing that the entire session has ended. Pause freezes the transport, speech and device output; explicit End session cancels live work. Bounded planning and retention still apply. A fixed duration remains available and retains its usual final closing and automatic end.

New profiles and legacy profiles still using the old 20-minute default adopt Unlimited. A versioned duration preference preserves subsequent explicit timed choices, including 20 minutes. Existing non-default timed preferences remain intact. Voice, mix, model, memory and device preferences are not reset. Original recordings and playlists use their actual media duration; imported authored programs retain their explicit finite timeline. Neither is silently looped. Unlimited does not affect request timeouts, trigger cooldowns, event durations or device heartbeat safety.

Unlimited validation covers three generated journeys with bounded retention, phase and trigger progress, extended absolute timestamps beyond 24 hours, speech metadata, device heartbeat timeout, Pause and Stop. The browser check accelerates playback past 20/40 minutes and 24 hours, verifies continued planning, then verifies a finite five-minute session still ends and its saved preference survives reload. These are scheduling checks with fixture speech, not a real day-long listening or hardware endurance test.

The director chooses an original bounded episode inside the current fixed parent phase. It considers delivered presentation density, recent episode use, introduced motifs, voice readiness, visual preferences, trigger reservations, remaining parent time and recovery/closing obligations. Near-equal legal choices use a session seed. It does not infer a listener's mental state. Planning keeps only one future episode within the existing 45-second preparation horizon, at most 64 live episodes, and 128 decision traces; it does not build an entire multi-hour script. `window.bambi.sessionEvents.decisions` exposes choices, scores, rejection reasons and readiness fallbacks for local debugging.

The initial vocabulary includes a soft ring/reflection, an original turning pink heart, linked gear graphics around a spiral, retained-motif passages, A/B fractionation, a prepared no-text blank with reanchor, narrative chapter resets, Original/Old Self, a three-iteration mantra, sparse/dark holds, staged peaks, recalls and soft returns. These are reusable authored grammars selected by policy, not a recovered reference timeline. Existing marker execution and the five 24/16/40/10/10 phases remain authoritative. Episode durations and selection weights are initial product tuning values, not measured source statistics.

Independent effect timing adds original short A–A–A–B impulses, a slower final-spacing variant and separate peak bed/effect envelopes. A dark picture can retain the bed and impulse lane while speech is absent. Quiet holds can remove the bed while retaining an impulse. Actual user faders and sound/visual preferences remain authoritative; these controls do not turn on disabled sources. Ring, heart and gears use local CSS/SVG geometry, with no new production dependency or reference assets. Reduced motion removes object motion and excludes the more animated gear/peak introductions. Low-intensity sessions omit layered peaks.

Each spoken slot has an engine-selected delivery profile and a measured audio deadline. Narration receives the current object/motion facts and up to 1,200 characters of the last actually played narration for continuity. Prefetched text never becomes that history. Voice-free intervals generate no text for themselves, but can prepare the following spoken window. The mantra renders one payload and the engine reuses it three times. The normal final closing uses brief original engine-owned text rather than asking the model to invent another ending.

Ordinary passages, peaks and non-final returns receive a separate phase-appropriate narrative focus, such as curiosity, comfort, attention, imagination or integration. The motif stays as truthful background context; these passages are instructed to develop the narrative rather than describe its shape, color or motion again. Introductions and brief recalls own those descriptions. Topic selection accounts for the preceding committed passage while preparation is ahead of playback; only actually heard speech enters delivered topic history. A silent fallback does not enter that history.

Motif recalls have a two-minute minimum interval and prefer a different already introduced object. A bounded six-episode history discourages repeated families even when another episode separates them. Conditioning peaks gain selection weight with elapsed time since the last peak, while density, low-intensity exclusion and mandatory recovery still constrain them. These are tuning choices, not guarantees that every session follows the same sequence or measured reference timings.

Renderer HTTP 429 enters bounded 1/2/4-second retries, with an 8-second cooldown after exhaustion. Before entry, missing speech replaces the voice-dependent episode with a restrained engine-only fallback at the same boundary. A late response cannot re-enable the removed speech, cue or haptic action. Pause cancels preparation and queued effect audio; Stop clears the plan, voices, effects and device cues. A programmatic seek in a generated session starts a fresh silent scene in the destination parent and prepares subsequent episodes, rather than pretending to scrub a prerecorded future. Imported programs and finished-file seeking retain their existing behavior.

Automated checks cover seeded sessions from one minute to six hours, parent boundaries, finite retention, density contrast, independent audio ramps, repeated-payload ownership, truthful screen facts, busy-renderer retry, missed-entry fallback, late responses, future preparation during a blank, seek and cancellation. Browser checks accelerate episode boundaries using silent speech fixtures and verify original motif graphics, busy-renderer recovery and paused clock behavior. They do not establish a real 20-minute listening experience, physical-device behavior or combined target-hardware performance. Those remain playback/profiling work, along with tuning the initial weights, separate supporting voices, more visual families and general phrase-to-action alignment.

The first integrated build passed 354 tests, TypeScript, repository checks and the isolated browser checks. A live local API closing render produced 5,248 ms of speech inside its 12,000 ms window with ten measured word onsets and no LLM generation. Its local WAV is retained in `.runtime/adaptive-closing.wav` for audition; this is a single voice-path check, not a completed session listening test.

The repetition correction passed 356 automated tests, TypeScript, repository checks and the web build. The isolated browser traversed 16 episode boundaries with all three forms, recovered from a simulated busy renderer, verified Pause and reported no page errors. Five seeded 20-minute policy simulations, with successor planning before current speech starts, reduced motif recalls from 16–19 to 5–7 and retained varied narrative focuses and resolved peaks. This verifies scheduling and text instructions; it does not establish that live generated narration sounds varied. Retained private comparisons are `.runtime/director-repetition-before.jsonl` and `.runtime/director-repetition-after.jsonl`.
