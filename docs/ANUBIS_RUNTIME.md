# Anubis Mini runtime

Anubis Mini uses the installed Q4_K_M weights through the project-owned native Vulkan runner. `python3 scripts/setup-anubis.py` verifies the pinned SHA256 and creates a hard link to the existing Ollama blob. It does not download another copy or replace that blob. The immutable source revision, size and hash are in [anubis-model.json](anubis-model.json).

The selected runtime window is **65,536 tokens**, with Flash Attention, one inference slot, six CPU threads and a `q4_0` K/V cache. The model metadata advertises **131,072 tokens**. That model capacity is distinct from a useful GPU runtime window: a 128K context cache plus weights exceeds the tested 8-GB GPU's memory budget. Larger context also increases processing time. The 64K cache trades some precision for capacity; contexts of 32K and below use `q8_0`. [Ollama's cache documentation](https://docs.ollama.com/faq#how-can-i-set-the-quantization-type-for-the-kv-cache) describes that precision/memory tradeoff.

The model supports the Llama 3 chat template. Native inference uses the GGUF's template and exact token counts before generation. Preparation checks the full selected prompt in conversation and every narration phase, then warms the fixed prefix. That prefix can be reused across following turns. A 1-GiB host prompt cache limits checkpoint storage. [Model card](https://huggingface.co/TheDrummer/Anubis-Mini-8B-v1).

Balanced sampling uses temperature `0.8`; Creative uses `0.95`. Both use top-p `0.95`, top-k `64`, min-p `0.02` and repetition penalty `1`. XTC and DRY are disabled for this model, including in the native runner's defaults. These are application tuning choices, not publisher guarantees. Context capacity, the configured sampler and a hash of the fixed prompt are available in health/preparation responses or local metrics.

Situational conversation now retains the entire selected authored prompt, enabled collar material and strategy. Its turn protocol determines whether to answer, ask, guide or close. Latest corrections, actual engine state and delivery rules resolve conflicting character examples. Requested language intensity is separate from the audiovisual buildup. [Conversation behavior](SITUATIONAL_CONVERSATION.md).

Validation includes transport and ownership tests, exact prompt-budget checks and live Anubis checks for factual answers, personal recall and a focused question. Long-context stress tests use synthetic archive data; their local reports are under `runtime/` and remain outside Git. Passing these probes does not guarantee adherence on every conversation or establish a hypnotic effect.

The 2026-10-06 probes retained the complete roughly 40,000-character authored document. All six conversation/narration budget checks fit. A 59,646-token request retained its entire archive and recovered three codes placed near its beginning, middle and end. Processing the roughly 45K new tokens took 306 seconds; large new inputs still take time. With an already cached prefix, the smaller factual/recall/question probes began responding in roughly 0.25 seconds. These measurements describe their test inputs, not a latency guarantee for arbitrary chats.

An interleaved listening decision also preserved the long prompt cache: the following reply reused 14,134 tokens and started in 2.18 seconds while processing its 514 changed tokens. Production app preparation with the saved Classic prompt, selected cues, Dual Voice and Bambi Classic voice succeeded in 35.55 seconds. Exact budgets left about 42K tokens for conversation after reserving an 8,192-token response. The final 64K profile uses a 64-token microbatch to reduce GPU workspace.
